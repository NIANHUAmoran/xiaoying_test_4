# 需求与验收标准

## 用户、目标与范围

面向需要制作产品介绍短视频的创作者。输入主题、受众、平台、目标时长和风格，结合可检索的产品素材与品牌规则，生成可编辑的结构化脚本。交付内容包括标题、分镜、画面说明、旁白或字幕、分镜预计时长、总预计时长、事实来源和任务状态。

本题的关键是让模型根据工具返回的信息改变下一步动作，并证明最终稿的事实和时长已经检查。实现采用 CLI，素材和品牌规则均为仓库内的合成数据。界面、视频生成、发布、账号接入、长期任务存储不在本次范围内。原题末尾的附件上传提示属于试卷界面说明，不是脚本产品功能。

## 输入与素材

| 输入项 | 约束与用途 |
| --- | --- |
| `theme` | 非空字符串，说明视频主题 |
| `audience` | 非空字符串，说明目标受众 |
| `platform` | 非空字符串，说明发布平台 |
| `target_seconds` | 1..600 的整数，表示预计总时长上限；布尔值不作为整数接受 |
| `style` | 非空字符串，说明表达风格 |
| 素材与品牌规则 | 由本地 world JSON 提供，不从用户输入中臆造产品事实 |

缺少必填字段，或字段值为 `null`、空字符串时返回 `needs_information`，列出需要补充的信息，不调用模型猜测。非法类型、纯空白文本、超出范围的时长等输入由校验器抛出 `ValueError`，CLI 输出输入错误并以退出码 2 结束，不生成任务成功结果。真实模型配置与业务输入分别提供；真实密钥不属于脚本输入或交付材料。

默认素材 P01 只提供产品事实“支持字幕”。它不能证明效率、准确率、用户数量、市场排名等效果。规则库给出允许的标题、画面说明、中性表达及禁止表达。更换素材的演示通过替换 world 文件完成，检查必须以当前工具实际检索到的事实为依据。

## 输出与状态

脚本以 JSON 表示，方便后续编辑：每个分镜具有稳定的 `id`、`visual`、`narration`、`subtitle`、`duration_seconds` 和 `source_refs`；每条引用记录 `material_id`、`fact_id` 和原文 `quote`。输出还保留实际修订稿、每稿的时长和规则检查、风险及运行记录。

| 状态 | 语义 |
| --- | --- |
| `completed` | 当前修订稿通过时长与规则检查，可以作为本次交付脚本 |
| `needs_information` | 输入缺少关键信息，需要用户补充 |
| `needs_materials` | 模型根据检索结果判断资料不足，需要补充素材 |
| `tool_failure` | 模型根据未恢复的业务工具执行错误结束，不能据此声称素材不存在或脚本合格 |
| `incomplete` | 当前条件无法满足、模型主动停止、执行上限耗尽或模型调用/响应格式错误，未产生合格终稿 |

只有完成状态提供可用终稿；未通过的内容放在明确标识的 `last_draft` 与 `revisions` 中供检查。历史草稿、失败结果与最终通过结果必须能够区分。

## 成功标准与验收场景

下表描述验收预期，不代表已经完成真实模型验证。实际命令、文件、执行结果与失败记录统一见 [03-evaluation.md](03-evaluation.md)。

| 场景 | 输入或工具条件 | 预期可观察行为 |
| --- | --- | --- |
| 正常生成 | 信息完整，P01 可检索，目标 45 秒 | 模型检索素材、提交脚本并调用两项检查，合格后输出标题、分镜、来源与总时长 |
| 缺关键信息 | 缺主题、受众、平台、目标时长或风格 | 返回 `needs_information` 和缺失项，不编造输入 |
| 无素材 | 检索返回空材料集合 | 模型根据观察改写查询，或结束为 `needs_materials`；不能捏造 P01 内容 |
| 工具失败 | 检索等工具返回明确失败 | Trace 记录失败；模型决定后续动作，无法恢复时明确返回 `tool_failure` |
| 超时长修正 | 目标 30 秒，首稿分镜时长为 20 秒与 18 秒，估时为 38 秒 | 模型看到超时长反馈后压缩并重新检查；例如改为 14 秒与 14 秒时得到 28 秒，全部通过后才能完成；也允许如实返回无法满足 |
| 事实和品牌违规 | 使用“效率提升 80%”、虚构事实、未知来源或不匹配引用 | 规则检查不通过，模型修订后复检，或明确停止；违规稿不得变为终稿 |
| 更换素材或目标时长 | 替换工具结果或目标时长 | 下一步动作与最终状态随观察调整，不能复用预设成功日志 |
| 防止沿用旧检查 | 检查后再次写稿 | 原检查对新稿失效，新稿必须重新估时与检查 |
| 达到执行上限 | 默认最多 20 次模型动作，或指定更小上限 | 返回明确未完成状态，保留已有观察，不无限循环 |
| 模型调用或格式错误 | 网络、服务、JSON 格式或动作结构不符合接口约定 | 返回 `incomplete`、`reason=model_error`，保留已完成的观察和草稿，不执行错误动作 |

至少提供正常、信息或资料不足、工具失败三组实际输入、输出和 Trace；材料还须覆盖超时长后的修正或明确失败，以及事实可追溯检查。真实模型至少呈现两条根据不同工具结果调整动作的路径。离线 Mock 的用例仅证明控制流程和防护行为，不证明真实模型的选择能力。

## 事实与时长边界

为使“无依据的效果结论不得出现”可执行，本实现使用受控表达：旁白和字幕中的每句只能来自本分镜精确引用的事实，或来自品牌允许的中性短句；标题和画面说明也使用允许列表。此约束便于审计，但牺牲自由改写能力。它不是任意自然语言的事实蕴含判断，也不证明任意主题、平台和风格都能生成自然、丰富的创意脚本。

时长按每个分镜的指定停留秒数、文字长度估算秒数和最小分镜时长取最大值，再求和。默认每秒 5 字、每景至少 2 秒。它用于发现明显超长并驱动修订，不能替代真实配音、字幕阅读和剪辑节奏测量。把长旁白的指定时长填为 1 秒不能绕过估算。
