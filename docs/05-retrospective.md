# 复盘、收获与下一步

## 最难的问题

本题最难的是让“有事实依据”和“满足时长”成为能够检查的交付条件。给脚本附上 P01 并不足以证明每句话：P01 只有“支持字幕”，不能支持“效率提升80%”，也不能替其他分镜中的产品结论背书。只要求模型填写分镜秒数同样不可靠，长旁白或长字幕可能被填写为 1 秒。

本实现把证据、估时与修订绑定起来。事实必须来自本任务实际检索的材料，引用要定位到事实并匹配原文，还要在使用该事实的分镜上出现。逐景估时取指定秒数、旁白字符估时、字幕阅读估时和最小 2 秒中的最大值。每次写稿创建新修订，清空当前的两项检查；只有同一最新修订的两项检查通过，运行时才导出成品脚本。

这一做法也使失败更容易解释：未通过的稿件保存在 `last_draft` 和 `revisions` 中，便于看到尝试过程；`script`、顶层分镜和来源只从通过检查的终稿导出，避免把草稿误当作完成结果。

## 有效的工程改进

先用本地工具与离线模型跑通“检索→写稿→检查→结束”的骨架，再加入资料不足、工具失败和修改后的复检约束，使每次扩展都有可复现的输入与输出。38 秒改为 28 秒的离线记录展示了时长反馈如何驱动下一次写稿；一景规则场景展示了另一类检查失败如何驱动删除分镜。两条路径分别见 [over-duration.trace.json](../examples/over-duration.trace.json) 和 [rule-limit.trace.json](../examples/rule-limit.trace.json)。

对抗测试比单独查看成功稿更能暴露边界。测试专门尝试把虚构结论藏入旁白、字幕、标题或画面说明，替换事实 ID 或引文，在新稿上复用旧检查，以及把长字幕的指定时长压低。评审还特别检查了“全部使用中性句、没有任何产品证据”的稿件；现在它必须收到 `no_product_evidence`，不能因为没有直接造假就被当作完成产品介绍。相关回归保留在 [test_agent.py](../tests/test_agent.py)。

截至本次文档整理，38 项测试和 11 个离线 CLI 场景已经实际通过，三条真实模型路径也已验证。真实模型的路径、状态、失败和最终复测结论统一查看 [03-evaluation.md](03-evaluation.md)，不把离线通过推断为真实模型通过。测试结果与运行记录保存在 `examples/`，评审可以依据数据复查结论。

真实超时路径首次在 38 秒检查后返回不可解析的 JSON，系统没有导出成品，而是保留了草稿、检查和未完成状态。后来增加完整外层 Markdown JSON 围栏的解析及脱敏错误行列信息，不修复任意损坏语法；重跑后模型把第二景从 18 秒缩至 10 秒，总时长 30 秒，并对新稿重新做两项检查。首次原始响应没有保存，无法确定其具体格式原因，不能将后续通过简单归因于围栏处理。历史失败与复测成功记录均保留。

## 主要取舍与局限

采用精确事实句、中性短句库以及预批准标题和画面说明，优先保证有限示例中的事实可追溯性。代价是表达比较固定，对受众、平台和风格的适配空间有限。它不是通用语义蕴含系统，也不等于开放式短视频创作产品。扩大自由度需要同步扩大证据检查能力，而不能仅放开文本字段。

时长工具可重复且便于测试，能阻止明显的低报；但每秒 5 字和最小分镜秒数只是本例参数。它没有测量真实 TTS、口播停顿、字幕排版、转场或剪辑节奏，28 秒是工具估算值，不是实测成片时长。

素材检索使用字面关键词，模型可以根据空结果改写查询，但这不具备语义检索的召回能力。任务状态保存在单次进程中，不支持跨进程恢复；本次也没有实现界面、成片生成、线上部署或发布。它们不属于题目必需范围，仍需在产品化时另行设计。

开发协作提高了实现与评审的并行度，但运行时保持单模型动作循环。可运行和测试通过不能替代提交者对代码的理解；目前没有收到考生独立修改与验证记录，不把这些 AI 协作结论写成考生个人学习经历。

## 下一步

1. 使用更多独立主题、资料缺失和模型异常样本评估真实模型；记录失败率、修订次数与调用成本，再决定是否扩大场景。
2. 在保留逐分镜来源的前提下扩展受控表达，评估可核验的同义改写；为更复杂材料建立事实级索引，避免仅依赖关键词检索。
3. 接入真实配音或字幕阅读测量，校准每秒字符数、停顿与分镜最小值，并把实测误差加入评估。
4. 由提交者复现命令、解释关键取舍并记录其实际修改；真实发布后填写 GitHub URL、最终 commit SHA 和评审权限。

本次实际用时与交付状态见 [delivery-status.json](../examples/delivery-status.json)。计时起点为 `2026-11-11 01:29:57+08:00`，结束时间以该记录的实际值为准；它包含 AI 协作和验证等待，不作为个人独立用时。远端仓库尚未发布时，不填造 URL 或 SHA。
