# AI 辅助、修改与验证记录

## 本次使用范围

本项目在 AI coding 协作中完成。用户提供第 4 题题目，要求沿用“先侦察、再定架构；先跑通骨架、分批补规则；用对抗测试验证；说明局限；提交前自查”的解题流程，以及规定的 GitHub 交付结构。既有的本地模型接口配置在用户授权范围内复用；项目交付目录只提供配置示例，不包含真实密钥。

AI 参与了需求整理、方案设计、代码实现、合成数据、测试、运行示例和文档编写。使用 Python 标准库实现运行时与 HTTP 接入，没有使用第三方 Agent 框架。开发过程中使用多个 AI 协作任务分担工作；实际运行的短视频脚本 Agent 是一个模型逐步选择动作的循环，业务执行中没有部署多个 Agent。

| 开发协作职责 | AI 辅助产物 | 核验方式 |
| --- | --- | --- |
| 主实现 | 输入与动作校验、修订状态、完成门槛、模型适配、CLI、复现与交付检查 | 正式命令运行、单元测试、实际输入输出与 Trace 对照 |
| 工具与数据 | 素材检索、逐景估时、事实引用与品牌检查、合成 world 文件 | 工具测试、修改素材与规则后的行为检查 |
| 验收与对抗测试 | 正常及失败路径、伪造事实和引用、时长低报、旧检查复用、无证据稿等测试 | 执行 `python -B -m unittest discover -s tests -v`，保存实际报告 |
| 需求与方案评审 | 需求、设计取舍、交付结构核查，检查文档与实现是否一致 | 对照题目、代码、运行结果和交付目录 |

## 用户输入与个人修改的边界

已知的用户参与包括提供题目、明确目录与交付规范、授权使用本地模型接口配置。没有收到考生独立编写代码、修改具体实现或自行运行验证的记录，因此本仓库不声称存在这些个人操作，也不把 AI 生成的修改登记为考生独立完成。

本次代码和文档的技术修改属于上述 AI 协作过程。提交者仍需能够解释实现、检查实际运行材料，并在后续自行修改或复验时补充真实记录。此处不代填理解程度、个人学习时长、独立完成比例或尚未发生的人工操作。

## 已执行的验证

本次本地验证已执行 38 项测试和 11 个离线 CLI 场景，另有三条真实模型路径通过。测试实际记录见 [test-results.txt](../examples/test-results.txt)，离线结果见 [offline-validation.json](../examples/offline-validation.json) 与 [run-summary.json](../examples/run-summary.json)。完整命令、验收映射、真实模型运行结果及失败情况以 [03-evaluation.md](03-evaluation.md) 为准。

验证重点包括：

- 30 秒目标下，首稿估时 38 秒，模型依据工具观察改为 28 秒，并对新修订稿重新估时和检查规则。
- 品牌规则限制为一景时，原两景稿检查失败，模型删除片尾景后对新稿执行两项检查；旧稿及失败结果仍保留。
- 修改 P01 事实后，生成的事实文字和引用随检索结果变化；未检索材料、虚构事实 ID、错误引文和“效率提升80%”不能通过。
- 正确引用不能为其他分镜或其他结论背书；全中性且没有产品事实证据的稿件也不能完成。
- 长旁白、长字幕不能用较低的指定秒数绕过估算；每次写新稿都会使当前两项检查失效。
- 空素材、工具失败和执行上限分别保留明确状态；临时工具故障恢复后仍可追查失败历史。

离线 Mock 按观察生成可重复的动作，用来验证运行时、工具及状态边界。它不证明真实模型具有同等决策效果。真实超时路径实际选择 38→30 秒，离线参考路径选择 38→28 秒，分别按原始结果保留。一次真实模型 JSON 格式失败也单独归档；随后增加完整外层 JSON 围栏兼容与脱敏位置诊断，重跑通过，不把首次失败改写为成功。Trace 的 `basis` 是简短、可核验的决策依据，不收集模型内部思维过程。

## 使用与交付限制

AI 生成内容经过本地测试和运行核验，仍不等同于生产级质量保证。事实检查依赖受控短句和精确引文，时长依赖启发式估算；两者的能力边界见方案与评估文档。项目没有声称支持任意主题的自由创作、真实配音测量或视频成片制作。

实际用时以 [delivery-status.json](../examples/delivery-status.json) 记录为准，统计包含 AI 协作、实现、验证和等待时间，不代表考生个人独立作答时长。GitHub URL、最终 commit SHA 和评审权限需要真实提交后填写；本地文件完成不代表已发布到远端仓库。
