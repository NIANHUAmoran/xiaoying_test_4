# 方案与技术取舍

## 执行方式与组成

使用 Python 3.12 标准库实现独立 CLI，不引入 Agent 框架。HTTP 模型适配器接入配置的大模型，离线 Mock 供无网络时复现控制流程。两种模式分别标识，运行记录不互相充当效果证据。项目不依赖前面几题的代码目录；安装、配置与命令见 [README.md](../README.md)。

运行时负责输入校验、动作格式校验、工具执行、修订状态、完成门槛与步数上限。模型负责读输入及真实工具观察，选择检索、写稿、检查、修订或结束。工具负责可重复的本地素材检索、时长估算和规则检查。素材和规则来自 `data/`，每个任务在独立的内存状态中执行。

## 动作与反馈循环

模型每次只提交一个结构化动作，包含动作名、参数和简短 `basis`。`basis` 描述可核验的依据，例如“估算 38 秒超过目标 30 秒，因此缩短分镜停留时间”，不要求或保存模型内部思维过程。

| 动作 | 作用 | 模型收到的观察 |
| --- | --- | --- |
| `search_materials(query)` | 检索本地素材 | 匹配材料、材料 ID、事实 ID 与原文，或空结果/明确失败 |
| `write_script(script)` | 提交完整新修订稿 | 结构校验结果与当前修订编号 |
| `estimate_duration({})` | 估算当前修订稿的时长 | 各分镜指定时长、文字估时、最终估时、总时长、是否超过目标 |
| `check_rules({})` | 检查当前稿的来源与品牌约束 | 是否通过、逐项问题、已核验的材料与事实引用 |
| `finish(kind)` | 请求完成、补材料、报告工具失败或停止 | 运行时校验完成条件后返回最终状态，或拒绝过早完成并继续反馈 |

`finish.kind` 支持 `complete`、`need_materials`、`tool_failure`、`cannot_meet` 和 `stop`。缺必填输入由运行时直接返回 `needs_information`，不浪费模型动作；非法类型或超范围输入作为输入错误拒绝，CLI 退出码为 2。默认最多执行 20 次模型动作；无效动作和失败尝试也消耗预算。预算耗尽后输出明确未完成结果。

预设骨架只规定安全边界，下一步动作来自模型返回值。检索空结果不会自动伪造材料或固定跳到成功；模型可以换查询，或要求补充。检查失败后，模型可以修改脚本再检查，也可以说明在现有条件下无法满足。是否恢复、是否修改及何时停止在 Trace 中可观察。

## 修订与完成条件

每次成功写稿创建新 revision，并清空当前稿的时长和规则检查。历史稿及对应检查保留为独立快照。`estimate_duration` 与 `check_rules` 总是检查当前稿，结果绑定该 revision；修改分镜后不能沿用旧稿的通过结果。

运行时仅在最新稿具有有效、通过的两项检查，并且存在实际用于脚本的有效产品事实引用时接受 `finish(complete)`。最终标题、分镜、来源与总时长由已检查的结构化稿件和工具结果导出，不采用模型另写一段未经检查的最终脚本。模型可以在发现超时长后直接放弃首稿并写新稿；历史只保留实际执行过的检查，不补造被放弃草稿的检查记录。未完成状态只保留明确标识的草稿和历史，避免把超时长或事实违规稿当作可交付终稿。

修订记录把三类信息对应起来：分镜 `id` 和素材引用、该稿逐景时长、该稿规则结果。Trace 额外记录动作顺序、参数、返回摘要、下一步动作和简短依据；因此既能看见“发生了修订”，也能检查修订是否真正通过。

## 事实与品牌校验

脚本使用严格字段结构；分镜 ID 不重复，秒数为正整数，文本及引用字段类型明确。材料引用必须已由本任务的检索工具返回，`material_id` 与 `fact_id` 能定位到事实，`quote` 必须精确匹配该事实原文。每个分镜的产品表达只使用其自身引用的事实，避免把某个正确来源挂在脚本上却在其他分镜编造结论。

旁白和字幕按句检查，每句必须等于引用事实或允许的中性表达；标题和画面说明使用品牌允许列表。禁止表达在可见脚本字段中统一检查。这样 P01 的“支持字幕”不能被扩展为“效率提升 80%”，也不能把虚构结论藏进标题或画面说明。引用存在但没有实际用于该分镜表达时，也不应作为有效支撑。

这是一个以可审计性为优先的受控生成方案。规则检查不调用第二个语言模型做自由语义判断，减少不可复现的“看起来合理”判定；代价是事实同义改写、开放式创意画面和自由标题可能被拒绝。用户主题、受众、平台和风格会提供给模型，但在有限素材和表达库内的适配能力有限。扩大素材库与表达能力需要同时扩展校验，而非直接放开未经验证的字段。

## 逐景时长估算

对每个分镜，分别计算旁白字符数与字幕字符数对应的阅读秒数，取较大值，避免同一句旁白和字幕重复计时；再与指定分镜秒数、最小分镜秒数取最大值。默认每秒 5 字，每个分镜至少 2 秒：

```text
speech_seconds = ceil(旁白有效字符数 / 5)
subtitle_seconds = ceil(字幕有效字符数 / 5)
estimated_seconds = max(duration_seconds, speech_seconds, subtitle_seconds, 2)
total_seconds = 各分镜 estimated_seconds 之和
```

有效字符数排除空白和标点。指定时长代表画面停留预算，文字估时提供下限。例如初稿两景为 20 秒与 18 秒，工具返回 38 秒；目标 30 秒时，模型根据反馈把两景改为 14 秒与 14 秒，并对新 revision 重做两项检查，才可能得到 28 秒的合格稿。目标 45 秒时，同一首稿没有超时长原因，是否继续修改由模型根据观察决定。离线 Mock 固定演示 38→28；真实模型可选择其他满足目标的修订时长，实际输出以 [03-evaluation.md](03-evaluation.md) 引用的记录为准。

估时使用启发式文字速度，不涵盖真实人声、停顿、音乐、镜头转场和平台字幕排版。工具给出“预计”时长，不宣称已生成或测量视频成片。

## 失败、日志与密钥

空检索结果是成功执行后返回零材料；业务工具异常是执行失败，二者分别返回并进入模型观察。模型可基于后续结果决定是否恢复；未恢复的工具错误不能被降格为“没有素材”，模型可据此选择 `finish(tool_failure)`。无效脚本结构作为工具观察反馈，供模型修订。模型调用失败、响应 JSON 无法解析或动作结构非法时，运行时立即以 `incomplete`、`reason=model_error` 结束，保留之前的实际记录；这些失败尝试也计入动作预算。

模型响应只解析 JSON 对象。适配器可以去除完整包住响应的外层 Markdown JSON 代码围栏，随后仍须通过 JSON 解析和动作结构校验；不会从任意前后说明文字中提取动作，也不会修复损坏 JSON。新记录可用 `model_output_format` 标明普通 JSON 或围栏 JSON。原始格式失败记录按当时实现原样归档，不追补未录制的元数据。解析错误仅记录格式和行列位置，业务记录不保存模型响应正文。

真实模型的 URL、模型名和 API key 从环境或显式指定的配置文件读取。交付目录只提供 `.env.example`，不复制真实 `.env`。网络错误和模型返回错误须经过处理，运行记录不保存请求头或密钥。业务材料全部为合成示例。

任务状态保存在单次运行内存中；CLI 可导出本次 JSON 和 Trace 作为验收材料，不实现跨任务恢复、持久化工作流或平台发布。没有使用第三方 Agent 框架，因此无需声明框架版本；Python 与实际模型接入信息、验证证据及已知限制见 README 和评估文档。
